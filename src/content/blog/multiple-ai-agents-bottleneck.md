# 複数 AI エージェント運用時のボトルネックを設計で解消 ― エグゼクティブ・レイヤーと権限設計にフォーカス

> **要点**  
> - **3 段階の権限レベル**（L1‑L3）を明確に分離し、ミスの影響影響範囲を抑える  
> - **フック設計**で AI に就業規則を自律的に守らせる  
> - **システムプロンプトの管理**を一元化し、変更を即座に反映  
> - **朝礼レポート**を AI 秘書が自動生成し、エグゼクティブは「今日何を決めるか」だけを見る

## 1. 権限設計の全体像 <a id="権限設計の全体像"></a>

AI エージェントが増えると、**「誰が何をできるか」** の管理がボトルネックになります。  
人間組織と同様に **権限レベル** を段階的に設け、**最小権限の原則** を徹底します。

```
L1 – オペレーター   →  タスク実行・データ取得
L2 – コーディネーター →  タスク割り振り・ステータス更新
L3 – エグゼクティブ   →  方針決定・予算承認・最終判断
```

この構造により、**ミスが起きても影響はそのレベル内に留まり**、上位層が全体を俯瞰できるようになります。

---

## 2. 3 段階の権限レベル詳細 <a id="3-段階の権限レベル詳細"></a>

| レベル | 主な権限 | 具体的なアクション例 | 権限ポリシー（JSON） |
|--------|----------|----------------------|----------------------|
| **L1 – オペレーター** | タスク実行、データ取得、レポート作成 | YouTube 動画編集、税務情報取得、コンテンツ校正 | `{ "max_concurrent_tasks": 5, "allowed_actions": ["create_note","fetch_data"] }` |
| **L2 – コーディネーター** | タスク割り振り、ステータス更新、他エージェント指示 | プロジェクト進捗管理、マーケティングプラン統合、パートナーシップ交渉の進行管理 | `{ "max_concurrent_tasks": 10, "allowed_actions": ["assign_task","update_status"] }` |
| **L3 – エグゼクティブ** | 方針決定、予算承認、リスク評価、最終判断 | 予算承認、事業戦略変更、リスク許容度の再設定 | `{ "allowed_actions": ["approve_budget","override_policy"] }` |

### 権限チェックの実装ポイント

1. **policy_check ユーティリティ**を全エージェントに組み込み、実行前に `allowed_actions` を照合。  
2. **違反時は自動エスカレーション**：L1 が未許可アクションを要求したら、リクエストは即座に L3 に転送し、ログに記録。  
3. **権限変更は Obsidian の「権限定義」ノートで管理**し、コミット履歴で変更履歴を残す。

## 3. フック設計 ― 就業規則を自律的に守らせる <a id="フック設計"></a>

AI に**「何をしてはいけないか」** を認識させるためのフックは、**システムプロンプト**と**ポリシーエンジン**の二層構造で実装します。

### 3‑1. システムプロンプトの固定部分（レベル別）

```text
# L1 – オペレーター
You are an Operator. Do not ask for approval before completing any task that is within your allowed_actions. If you need a decision, forward the request to a Coordinator.

# L2 – コーディネーター
You are a Coordinator. You may delegate tasks to Operators and update task statuses. For any action outside allowed_actions, forward to an Executive.

# L3 – エグゼクティブ
You are an Executive. You make final decisions, approve budgets, and can override policies when necessary.
```

### 3‑2. ポリシーエンジン（JSON）とチェックロジック

```json
{
  "L1": { "allowed_actions": ["create_note","fetch_data"] },
  "L2": { "allowed_actions": ["assign_task","update_status"] },
  "L3": { "allowed_actions": ["approve_budget","override_policy"] }
}
```

**実装イメージ（Node.js）**

```js
function policyCheck(level, action) {
  const policy = policies[level];
  if (!policy.allowed_actions.includes(action)) {
    // エスカレーション用メッセージを生成
    return {
      allowed: false,
      escalation: `Action "${action}" not permitted for ${level}. Escalate to L3.`
    };
  }
  return { allowed: true };
}
```

### 3‑3. フィードバックループ

- L3 が判断ミスやポリシー違反を検知したら **Obsidian の「フィードバック」ノート**にコメント。  
- 次回同様タスクが来たとき、**policy_check** が過去フィードバックを参照し、**ルールベースの学習**を行う（シンプルなホワイトリスト/ブラックリストの更新で十分）。

## 4. システムプロンプトの一元管理と更新フロー <a id="システムプロンプトの管理"></a>

### 4‑1. ファイル構成（Astro プロジェクト内）

```
src/
 └─ content/
     └─ prompts/
         ├─ l1.md
         ├─ l2.md
         └─ l3.md
```

- 各ファイルは **Markdown** 形式で保存し、**Git** でバージョン管理。  
- 起動時に `loadPrompts()` が全ファイルを読み込み、**レベル別にキャッシュ**。

### 4‑2. 更新手順

1. **Obsidian で対象行を編集** → **Git commit** でプッシュ  
2. デプロイ時に **`npm run build`** が自動で最新プロンプトを取得し、AI エージェントに配布  
3. **変更は即座に反映**：次回エージェント起動時に新プロンプトがロードされるだけ  

このフローにより、**人間が権限や規則を変更したらすぐに AI が従う** 仕組みが実現します。

## 5. 朝礼レポート：エグゼクティブが見る情報だけに絞る <a id="朝礼レポート"></a>

エグゼクティブ層は **「今日何を決めるか」** のみを把握すれば良いように、**AI 秘書** が以下の手順でレポートを生成します。

1. **タスク集約**：全 L1/L2 エージェントが **「今日の判断が必要なタスク」** を共有データベース（例：JSON ファイル）に投稿。  
2. **要約エージェント**がカテゴリ別にスコアリングし、重要度順に並べ替える。  
3. **AI 秘書**が Markdown 形式でレポートを作成し、**メール/Slack DM**で配信。  

### サンプルレポート（Markdown）

```markdown
# 今日のエグゼクティブ・レポート（2026‑06‑27）

## ビジネス
- **A社パートナー交渉**：最終提案期限 18:00（要承認）  
- **広告予算**：$15,000（要決裁）

## エンジニアリング
- **YouTube 自動編集パイプライン**：ステージング完了、デプロイ可否の判断が必要  
- **法務ドキュメント自動生成**：テストエラー 2 件（修正方針決定）

## コンテンツ
- **次回ブログテーマ**：候補 3 件（採用方針確認）  
- **Podcast 脚本**：レビュー待ち（公開可否判断）
```

**エグゼクティブはこのレポートを読んで**  
- **承認/却下**の指示を返信  
- **AI 秘書**が指示を各エージェントへ即時配信し、タスクステータスを自動更新  

結果として **「判断だけがボトルネック」** になることを防ぎます。

## 6. 実装ロードマップと次のステップ <a id="実装ロードマップ"></a>

| フェーズ | 目的 | 主な作業 |
|----------|------|----------|
| **0️⃣ 基礎** | 権限レベルとポリシーをコード化 | `policies.json` と `policy_check` ユーティリティの実装 |
| **1️⃣ プロンプト管理** | システムプロンプトを Obsidian ↔ Astro に連携 | `src/content/prompts/` 配下に Markdown を配置、Git フローを確立 |
| **2️⃣ フック設計** | 就業規則の自律的適用 | ポリシーエンジンとエスカレーションロジックを全エージェントに組み込み |
| **3️⃣ 朝礼自動化** | エグゼクティブが見る情報だけに絞る | タスク集約 API、要約エージェント、AI 秘書の 3 つのコンポーネントを構築 |
| **4️⃣ テスト & デプロイ** | 変更が安全に反映されるか検証 | ユニットテスト、ステージング環境でのフルフロー確認、`npm run build` で Astro デプロイ |

### 直近のアクション（3 日以内）

1. **`policies.json`** をリポジトリに追加し、`policy_check.js` を作成。  
2. **Obsidian の「システムプロンプト」ノート**を 3 つの Markdown ファイルに分割し、`src/content/prompts/` にコミット。  
3. **AI 秘書用の簡易レポート生成スクリプト**（Node.js）を作り、手動で 1 件テスト実行。  

---

## 終わりに

この設計は、**AI エージェントが増えても「判断のボトルネック」だけが残る** 状態を防ぎ、**エグゼクティブは価値創造に集中できる** 環境を提供します。

- **権限レベル**でミス拡散を抑制  
- **フック設計**で規則遵守を自律化  
- **システムプロンプト**で変更を即時反映  
- **朝礼レポート**で情報量を最小化  

これらを段階的に導入すれば、AI 主導の組織でも **「自分は昇進できる」** という実感が得られるはずです。
